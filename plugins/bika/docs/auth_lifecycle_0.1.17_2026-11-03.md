# 哔咔漫画+ 0.1.17：后台重试与会话写入

本次保持原插件启动时的自动登录/签到政策、站点接口、账号及记录身份，只限制失败重试，并保护手动登录、退出和密码更新不被旧任务覆盖。没有新增 UI、线路、账号迁移、真实账号操作或发布。

## 真实失败与修复

新增 `tests/auth-lifecycle.test.ts` 使用真实 Axios 处理链与合成存储桥，先复现两个失败：

- 登录 token 写已开始但尚未完成时退出，旧写在退出后完成，将 `auth.authorization` 恢复为旧任务的 token。
- 凭据已被明确拒绝，后台仍在 20–300 秒后再次登录，没有尝试次数上限。

失败记录在本机 `Breeze/build/bika-classic-bootstrap-20261103/auth-lifecycle-before.log`，两项都实际失败，不以代码审查代替复现。

`bika-auth-session.ts` 管理同一 JS runtime 内的统一代际和写入队列，`bika-checkin.ts` 保留原导出。登录、退出和密码更新共用队列：后续清理必须等已经启动的所有写入结束，哪怕其中一个先拒绝，也要等其余写入 settle 后再放行。同一 runtime 的旧代际不能新发请求、提交结果或排入新写入。队列失败不会阻塞后续正常登录；底层存储失败会返回失败，不宣称多字段具有数据库事务原子性。

后台同时只有一个运行中的 Promise，完整流程最多三次总尝试，等待 1 秒、2 秒后再次核对代际。保留原登录后读取真实资料/签到的流程；已签到不重复提交，未确认不宣称签到成功。凭据拒绝、401/403、取消与未知错误直接结束；只有明确 HTTP 429/5xx 或既有瞬态网络 code 可重试。错误不靠消息文字推测，不保留 Axios 原请求、body、headers 或 cause。

`plugins/shared/transient-retry.ts` 抽取 JM 原有无源标识的重试逻辑；JM `errors.ts` 保留 `JmRequestError` 名称及 `isTransientError` / `retryTransient` 导出，既有调用点不改，仍为原先的三次尝试、1s/2s 退避。它不共享源 ID、账号、缓存或运行中状态。

## 追加发现：跨网络 runtime 的宿主边界待收口

宿主允许同源 `source@net.*` runtime 同时存在，持久配置桥则 canonicalize 到同一个 source。两份 JS 状态的代际/队列互不可见。已用 0.1.17 真实 CJS 的两个隔离 VM 及共享 canonical 配置桥复现组件边界：旧 VM 的登录响应挂起，新 VM 退出清空，旧响应释放后又写回 token。它没有打开网络、没有真实用户资料，也不是完整 SDK/设备流程验收。

脚本及失败结果仅在本机 `Breeze/build/bika-classic-bootstrap-20261103/probe-cross-runtime.cjs` 与 `auth-cross-runtime-probe.log`。93 项同 runtime 测试和独立插件隔离测试不能替代这个跨 runtime 场景。已交主任务评估源级宿主 epoch/条件写入，或在明确账号操作时取消同源旧认证任务；本插件子任务未修改宿主桥，不能声称跨 runtime 会话复活已经修复。
