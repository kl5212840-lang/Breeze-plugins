# OmoFun 视频插件

首版使用 Breeze 视频协议 2，需配套本轮客户端。片库、完整搜索、分类与年份筛选、周更、榜单、专题沿用源站真实数据；本机收藏、文件夹、续播和记录由 Breeze 保存，和原站账户追番分开。

搜索或筛选遇到“继续访问”时，客户端显示原站页面，用户正常完成后回到原来的结果。验证会话保留在同一个 WebView；不导出 Cookie，不假定一次验证永久有效，也不自动循环提交验证。

分集以作品路径哈希、来源 sid、分集 nid 定位，临时媒体地址在播放前解析。线路名称、数量和顺序来自当前作品的真实分集链接，不固定为三条或四条。播放时读取该来源的实际静态播放器模板，仅解析受限的字面量/数据拼接，获取它声明的 HTTPS iframe；不在宿主执行源站脚本，不固定来源代码或解析服务器。未知模板明确失败并保留网页入口。源站外部线路的 403、404 或超时不能由插件保证消除；网页生成的 Blob/HLS 改写流程也不能仅靠取到原始媒体 URL 等同完成原生适配。

官方解析链失败后，仅当该集原始数据本身为公开 HTTPS `.m3u8` 地址，最多追加一次四秒 GET 验证；响应须为实际 HLS 主/子清单，并限制候选正文大小。验证失败保留原始解析错误，不把 HTTP 200 或 HEAD 成功当成播放成功；实际播放仍由原生播放器判定。不使用 opaque token、Blob/Data、MP4 或私网地址作此兜底，不改写签名和分段。媒体及验证请求的显式来源头保持一致，尊重原站明确的无 Referer 策略，不复制 Cookie 或伪造浏览器 User-Agent。

`capabilities.rawHlsRecovery=true` 声明显式懒恢复：新客户端在实际媒体失败且当前候选耗尽后，可对同一 `id/lineId/episodeId` 请求 `getSession({rawHlsRecovery:true,...})`。该请求重读源站分集数据并验证原始 HLS，跳过模板与解析服务；正常首播不提前做这次探测。宿主负责每个观看身份的次数、取消和换线边界，旧客户端忽略此可选能力。

配套客户端提供站点登录、官方追番、评论/回复阅读及作品讨论入口；需验证或编辑资料的操作仍可在原站网页完成。本机收藏与站点账号体系分开，会话目前保留于本机 WebKit，未接入账号云端恢复。原生弹幕和推广统计未接入。接口、字段及证据保留在 Breeze 的 `docs/video_source_api` 数据库；声优是演职员资料，不冒充作者主页。

`entry.cjs` 为维护源码，`source.json` 为唯一配置；运行 `node script/build-video.cjs` 生成独立可安装的 `omofun-native.cjs` 和清单。
